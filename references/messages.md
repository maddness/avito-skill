# Личные сообщения

«Комментарии» по объявлению здесь означают личные сообщения покупателей. Публичные отзывы не входят в этот сценарий.

```text
CLI own list
CLI own list --status all
CLI inbox list
CLI inbox list --items ITEM_ID,ITEM_ID
CLI chat read --id CHAT_ID
```

`own list` читает личный кабинет. `--status all` включает активные объявления и архив; удалённые объявления и черновики не перечисляются. Товары из фильтра мессенджера нельзя считать своими: там присутствуют товары других продавцов.

`inbox list` по умолчанию сканирует активные собственные объявления. Для явно указанных ID проверяется принадлежность и активность. Смотри `complete`, `history_complete`, `checkpoint_advanced`. Неполный ответ не доказывает отсутствие вопросов; скрипт не продвигает checkpoint при неполном обходе. Первый полный проход имеет `baseline=true`, поэтому `new_since_previous=null`: это исходная точка, а не ноль новых сообщений.

Покажи товар, собеседника, последний входящий вопрос и `awaiting_reply`. Системные уведомления не считай интересом покупателя. `unread`, новое после предыдущего прохода и ожидающее ответа — отдельные признаки. Команды не вызывают mark-read, но поведение серверных read-флагов всё равно задаёт Авито.

Перед ответом прочитай историю. Используй подтверждённые владельцем сведения и карточку. Не выдумывай размер, комплект, состояние или готовность к сделке. Если факта нет, уточни его у владельца либо отправь разрешённый нейтральный уточняющий вопрос.

```text
CLI message prepare --chat CHAT_ID --text-file MESSAGE_FILE --intent REQUEST_REF
CLI message send --operation UUID
CLI message verify --operation UUID
```

Подготовка не отправляет сообщение. Отправка сохраняет `random_id` и проверяет ровно одно соответствующее исходящее сообщение в истории. После таймаута проверка ищет тот же random_id; отсутствие доказательства доставки оставляет исход неизвестным. Обычный повтор пользователя с новым смыслом получает новый intent, технический повтор того же поручения — прежний operation_id.
