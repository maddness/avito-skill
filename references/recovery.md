# Ошибки и восстановление

| Наблюдение | Следующее действие |
|---|---|
| `AUTH_REQUIRED` | Прекрати текущие API-запросы. Для повторного подключения используй `CLI auth login` и передай ввод владельцу; готовый экспорт можно подключить через `session import`. |
| `ACCESS_OR_CHALLENGE` | Сообщи, что доступ/проверка не пройдены. 403 не доказывает истечение cookie. Для согласованного повторного входа открой `auth login`; проверки проходит владелец. Не повторяй неуспешные API-запросы циклом. |
| `PROFILE_MISMATCH`, `ITEM_OWNER_MISMATCH` | Останови запись. Сверь выбранный профиль и ID товара; не переключай аккаунт автоматически. |
| `RATE_LIMITED` | Соблюди retry_after_seconds. Не запускай новые процессы ради обхода cooldown. |
| `NEEDS_FIELDS`, `LOCATION_AMBIGUOUS` | Уточни факты/вариант, обнови JSON и повтори prepare. |
| `FREE_PUBLICATION_REQUIRED` | Сообщи, что бесплатное действие не подтверждено. Не оплачивай и не выбирай тариф. |
| `BUSY` | Дождись уже запущенной команды. После аварии lock может остаться; PID между контейнерами не доказывает, что владелец умер. Удаление lock допустимо только отдельным операторским действием после проверки отсутствия исполнителя. |
| `ITEM_CHANGED`, `PREPARATION_SUPERSEDED` | Перечитай состояние; новый preview и intent вместо применения устаревшего снимка. |
| `OPERATION_SUPERSEDED` | Старый receipt не соответствует текущему состоянию. Покажи текущие данные; для нового поручения создай новый intent. |
| `*_SCHEMA_CHANGED`, `*_UNSUPPORTED` | Зафиксируй код и ограничение. Не изобретай API и не меняй готовые скрипты во время использования скилла. |
| `DRAFT_OUTCOME_UNKNOWN` | Исход сохранения черновика неизвестен. Не создавай ещё один черновик вслепую; нужна отдельная проверка оператором. |

## Внешняя запись с неизвестным исходом

1. Сохрани operation_id из prepare/вывода. Получи `CLI operation status --id UUID`.
2. При `unknown`/`submitting` выполни соответствующее `sell verify`, `message verify`, `edit verify` или `withdraw verify --operation UUID`.
3. Проверка не повторяет исходный submit/send. Для публикации она может довести **уже заданные** настройки доставки после проверки созданного item_id. Это завершение известного объявления, а не новая публикация.
4. Если ID публикации не успел сохраниться (`PUBLICATION_ID_UNKNOWN`), покажи ограничение и проверь own list. Автоматическое присвоение похожего объявления операции не реализовано. Сохрани журнал; не меняй статус в JSON и не создавай новый intent/набор фото для обхода защиты.
5. Для `delivery set` с неизвестным исходом прочитай `delivery get`. Приведи точный наблюдаемый набор методов; автоматическое снятие unknown в журнале доставки не реализовано. Это операторский recovery, не повод повторять mutation с новым intent.

`prepared` означает готовность к действию, `submitting` — попытку, `unknown` — отсутствие достаточного доказательства результата, `succeeded` — проверенный результат на указанное время, `rejected` — подтверждённую ошибку без эффекта. Исторический receipt не доказывает текущую активность: для неё прочитай own list или карточку.

Установка задержки 300–600 мс не является обходом проверок Авито. Скрипты выполняют запросы последовательно, учитывают общий lock/cooldown и не повторяют записи автоматически. При блокировке остановись, сохрани результаты независимой части и сообщи владельцу конкретный следующий шаг.
