# Собственные объявления

## Подготовка товара

Собери: реальные фото, название, описание, цену, состояние, город и улицу, выбор доставки. Отдельно проверь работоспособность, дефекты и комплект. По фотографии нельзя гарантировать работоспособность, подлинность, объём или наличие невидимого аксессуара. Для иллюстрации дополнительных ракурсов предложи владельцу снять товар; фотографии чужого товара и сгенерированные «доказательства состояния» не публикуй.

Найди категорию и обязательные характеристики:

```text
CLI category find --query "Наушники Sony PlayStation PULSE 3D"
CLI category schema --id CATEGORY_CHOICE --title "Название товара"
CLI category option --id CATEGORY_CHOICE --field FIELD_ID --query "Sony"
```

Выбери наиболее конкретный `is_leaf=true` по пути категории. `category_choice` — ID узла навигации, не categoryId. Скрипт объединяет подсказку Авито по названию с деревом категорий. Если предлагаются разные товарные классы, сопоставь предмет и пути; при неоднозначности уточни. Не копируй ID категорий/enum из другого объявления. `NEEDS_FIELDS` показывает недостающие значения; ищи варианты через category option, заполняй только подтверждённые факты.

Создай JSON по [шаблону](../assets/listing.example.json). `attributes` содержит точные названия полей или их ID и выбранные значения. `photos` — абсолютные пути к реальным JPEG/PNG. Цена — целые рубли. Для самовывоза укажи `location.query` в формате «город, улица» и `precision:"street"`; номера домов этот режим отклоняет. Доставка должна быть явным boolean.

```text
CLI sell prepare --spec LISTING_JSON
CLI sell publish --operation UUID
```

Prepare загружает фото, подписывает адрес, сохраняет черновик, перечитывает его и проверяет нулевую плату. Это реальные изменения черновика, но не публикация. Проверь preview: профиль, товар, цена, категория, адрес, фото, доставка, плата 0. При уже данном разрешении пользователя выполняй publish. Если разрешения нет, покажи этот preview и запроси его один раз.

Publish отправляет форму единожды, записывает item_id и проверяет результат. Фото с теми же байтами в другом порядке не создают новый товар. Если publication status неизвестен — `sell verify --operation UUID`. Новое фото того же товара не является разрешением на дубль: сначала проверь own list.

## Описание

```text
CLI edit prepare --item ITEM_ID --text-file DESCRIPTION_FILE --intent REQUEST_REF
CLI edit apply --operation UUID
CLI edit verify --operation UUID
```

Меняется только описание. Скрипт читает актуальную форму, сохраняет остальные значения, проверяет версию перед записью и сверяет результат, включая фото, цену, параметры, контакты и доставку. `ITEM_CHANGED` означает, что владелец или сайт изменил объявление после подготовки; перечитай карточку и подготовь новый preview с новым intent. Не применяй старую форму вслепую.

Эта версия редактирования поддерживает обычные личные объявления с contactMethod `any`, без нескольких единиц товара, автопубликации и Pro-звонков. Для других схем возвращается явное ограничение; данные не обнуляются ради прохождения валидации. Смена цены, категории и фотографий готовой карточки не реализована.

## Доставка

```text
CLI delivery get --item ITEM_ID
CLI delivery set --item ITEM_ID --enabled true --intent REQUEST_REF
CLI delivery set --item ITEM_ID --enabled false --intent ANOTHER_REQUEST_REF
```

`true` включает обычную Авито Доставку в пункты выдачи (`delivery`), остальные поддержанные способы выключает. `false` проверяет и выключает все включённые способы из поддержанного набора. Неподдержанный включённый DBS-метод вызывает ошибку, а не ложный успех. Подключение субсидий продавца, платных акций, своих курьеров и оформление отправки не входит в команду.

После публикации всегда перечитываются все способы: выключенные PVZ/CNC в форме не гарантируют выключенного Postamat. Для включения доставка должна быть доступна конкретному товару. Новый пользовательский переключатель получает новый intent. Старый успешный operation не принимается за текущее состояние: оно проверяется заново.

## Снятие

```text
CLI withdraw reasons --item ITEM_ID
CLI withdraw run --item ITEM_ID --intent REQUEST_REF
CLI withdraw verify --operation UUID
```

Команда выбирает полученную от сервера «Другую причину», не меняет цену и не сообщает о состоявшейся продаже. Проверка подтверждает архивный statusId 11 и отсутствие в поиске. Объявление не удаляется. Возврат из архива/повторная публикация не реализованы; не создавай дубликат вместо восстановления.
