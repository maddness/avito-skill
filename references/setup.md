# Подготовка и сессия

Скилл рассчитан на локальный агент с shell, Node.js 22+ и HTTPS-доступом к `www.avito.ru`. Все библиотеки — встроенные в Node. Установка npm-пакетов, сервер и браузер для обычных операций не нужны. Изолированная среда без исходящего HTTPS или Node не подходит; загрузка ZIP сама по себе этих возможностей не добавляет.

Определи абсолютный путь к каталогу этого скилла по открытому SKILL.md. Далее `CLI` означает `node <skill-dir>/scripts/avito.mjs`. В командах замени обозначения реальными аргументами. Запускай:

```text
node --version
CLI help
```

Node ниже 22 → сообщи требование. Для первого подключения или при `FILE_NOT_FOUND` запусти `CLI auth login --state-dir PRIVATE_DIR` и покажи пользователю `ui_url`. Готовая сессия проверяется командой `CLI session status --state-dir PRIVATE_DIR`. При `AUTH_REQUIRED`/`ACCESS_OR_CHALLENGE` действуй по recovery.md. Не удаляй cookie и browser profile ради устранения ошибки; вход проходит в сохранённом или отдельном профиле, описанном в authentication.md.

## Первый вход

Для нового подключения выполни `CLI auth login` и покажи пользователю возвращённую `ui_url`. Помощник откроет Chrome, дождётся ручного ввода и проверок и сохранит подтверждённую сессию. Полный маршрут, повторный вход и удалённый браузер — в [authentication.md](authentication.md). Пароль вводится только на Авито и не хранится скиллом.

## Импорт готовой сессии

Если авторизованный экспорт уже есть, можно импортировать его без запуска браузера.

Передай **путь** к закрытому JSON-файлу, не значения cookie через командную строку или чат:

```text
CLI session import --file PRIVATE_SESSION_JSON --profile PROFILE_ID --state-dir PRIVATE_DIR
CLI session status --state-dir PRIVATE_DIR
```

Формат файла: объект `profile_id` (строка) и `cookies` (массив объектов с `name`, `value`, `domain`, `path`, `secure`, `expires`; совместим с обычным экспортом browser context). Дополнительные browser storage поля игнорируются. Источник должен иметь права 0600. Скрипт оставляет только домены Avito, проверяет текущий профиль через HTTP и лишь после успешной проверки атомарно заменяет рабочую сессию. Неверный импорт сохраняет прежнюю.

Используй отдельный `PRIVATE_DIR` для каждого профиля, вне скилла и репозитория. По умолчанию это `$XDG_STATE_HOME/avito`, иначе `~/.local/state/avito`. `AVITO_SESSION_FILE` с абсолютным путём переопределяет файл сессии; по стандартному пути переменная не обязательна. Каталоги 0700, файлы 0600. Путь можно передавать; содержимое session.json читать/выводить агенту не требуется. Linux проверен; другие ОС требуют отдельной проверки прав и совместимости.

Обновление: повтори `auth login` либо импортируй новый разрешённый экспорт командой `session import`. Связь профиля и журнал операций сохраняются. Это не OAuth access/refresh token: используется набор cookie с доменом, путём и сроком действия. Не обещай автоматическое продление или перенос сессии на любую машину.

## Вывод

Успех: `{"ok":true,"command":"...","result":{},"http_calls":N}`. Ошибка: `{"ok":false,"code":"...","details":{}}` и exit 1. `--output PRIVATE_JSON` сохраняет только result с правами 0600. В stdout возвращаются данные операции, без cookie/заголовков. Сохраняй переписку и локальные файлы результата как приватные данные.

Сначала выполни `help`, если команда в инструкции отсутствует или отличается от установленной версии. Неподдерживаемый контракт — причина сообщить ограничение, а не писать обходной fetch/curl/browser-код.
